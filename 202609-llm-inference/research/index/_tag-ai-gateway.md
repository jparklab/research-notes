- [[llm-cost-attribution-and-team-budget-tracking]] — LLM Cost Attribution and Team Budget Tracking — TrueFoundry (AI Gateway vendor) engineering blog on gateway-level LLM cost attribution, published Sep 11 2026. Core argument: provider-native billing aggregates at the credential boundary (Anthropic by API key, OpenAI by project, Azure by deployment/resource group, Bedrock by IAM role/account), never at the team/app/feature boundary organizations actually want to charge -- so attribution must happen at the gateway, the one point every provider call already routes through. Mechanism: an X-TFY-METADATA JSON header set per-request by the calling application (team/app/feature/env/user_id/etc.), with low-cardinality fields (team, app, feature, env) projected to metric labels and high-cardinality fields (user_id, pipeline_id) kept on the trace only to avoid metric-storage explosion; metadata auto-propagates across fallback and multi-turn/agent spans. Per-trace cost is computed at span close from a versioned (provider,model)-dated pricing table applied to gen_ai.usage token counts, explicitly subtracting both cache-read AND cache-write tokens from the 'fresh' input count before pricing (a documented common bug is subtracting only cache-read, double-counting cache-write). Aggregation is three-layer pre-aggregation (per-minute in-memory counters to hourly ClickHouse/TimescaleDB rollup to daily team x app x model materialized view) because querying raw trace volume (millions of spans/day) directly is cost-prohibitive. Budget enforcement is two-tier: soft alerts at 80% (PagerDuty/Slack, no blocking) and hard limits at 100% returning HTTP 429 with a budget_exhausted error; the check-then-spend race under concurrent requests is resolved with an atomic Redis INCRBYFLOAT counter incremented pre-dispatch and reconciled against actual cost at span close -- deliberately over-counts on aborted requests rather than under-counting. Budget-aware routing degrades gracefully (e.g. Sonnet to Haiku at 80% utilization, output-token cap added at 95%) rather than hard-cutting to 429. Chargeback report schema is the daily rollup grouped by team/app/model/provider with a cache_savings_usd column often representing a third to two-thirds of spend for agents with stable system prompts.
