- [[data-layer-llm-d]] — Data Layer | llm-d — llm-d dev docs, canonical Data Layer design page -- the single most direct answer to 'where do pod/Kubernetes assumptions live and what are the plugin interfaces.' Defines the Data Layer as a Source -> Extract -> Attribute pipeline enriching thread-safe/type-safe Endpoint objects. Names THREE extension-point interface pairs: (1) PollingDataSource + Extractor -- periodic pull, e.g. metrics-data-source (polls a Prometheus-compatible /metrics endpoint of a model server) + core-metrics-extractor (multi-engine-aware, maps engine-specific metric names to standard internal keys like KVCacheUsagePercent/WaitingQueueSize); a Collector goroutine is started per endpoint by the runtime. (2) NotificationSource + NotificationExtractor -- reacts to Kubernetes resource changes; concrete k8s-notification-source watches a single configurable Kubernetes GVK (CRD or core API) and is bound to the controller-runtime manager, dispatching NotificationEvents on create/update/delete (docs note: 'There are currently no upstream extractors that require this source' as of this snapshot). (3) EndpointSource + EndpointExtractor -- reacts to EPP-internal endpoint lifecycle events (add/update/delete) via endpoint-notification-source, independent of Kubernetes, for cache init/cleanup. CRITICAL FINDING for non-k8s backends: only the NotificationSource/k8s-notification-source pairing is intrinsically Kubernetes-coupled (it binds to controller-runtime and watches a GVK); the PollingDataSource and EndpointSource interfaces are backend-agnostic by design -- metrics-data-source polls whatever URL/address an Endpoint object carries, and endpoint-notification-source only reacts to endpoints already in the EPP's own datastore regardless of how they got there. This means the actual Kubernetes-pod dependency is concentrated in whichever DataSource populates the endpoint datastore in the first place (the pod/endpoint discovery mechanism itself), not in the metrics-polling or endpoint-lifecycle machinery. `evergreen`
