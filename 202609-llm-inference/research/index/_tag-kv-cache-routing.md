- [[flash-indexer-a-story-of-inter-galactic-kv-routing-nvidia-dynamo-documentation]] — Flash Indexer: A Story of Inter-Galactic KV Routing | NVIDIA Dynamo Documentation — NVIDIA Dynamo engineering blog documenting the design evolution of the Flash Indexer, the default global KV-block index shipped in Dynamo v1.0.0, which sustains over 100 million operations/second and is presented as an alternative KV-event-synchronization architecture to compare against llm-d's own routing/indexer design. Every cached block carries a local (chunk) hash (position-independent, content-only) and a sequence hash (rolling hash over the full prefix, position-dependent) plus a worker ID; a sidecar publisher per engine emits explicit Store(worker_id, local_hash, seq_hash) and Remove(worker_id, seq_hash) events over pub/sub because eviction policies (LRU sweeps, memory pressure, preemption) are opaque and cannot be inferred from request/response cycles alone. The design went through six iterations: (1) a Python nested dict, O(W*D) per query; (2) a single-threaded Rust actor eliminating interpreter overhead but serializing all reads behind writes; (3) an inverted index (local_hash -> seq_hash -> worker set) cutting query cost to O(D+W) but reintroducing rolling-hash computation on reads and expensive full-index scans on removes; (4) a radix tree keyed by parent-child local-hash relationships (requiring a new parent-hash field in KV events) that scopes hash-collision risk to shared-prefix siblings only; (5) a concurrent radix tree using Arc<RwLock> plus DashMap-sharded per-worker lookup tables and sticky per-worker-ID thread routing for writes, removing the actor bottleneck for reads (parking_lot::RwLock cited as 2-3x faster than std due to no syscall on uncontended paths); (6) the Flash Indexer itself, a Vec<DashMap> positional index enabling O(1) random access to any prefix position and a 'jump search' that skips ahead by a tunable jump_size (default 64) and only backtracks to find exact worker drain points on a partial-cardinality mismatch, giving amortized O(D/J + W) query cost. Benchmarked on a 24-core Arrow Lake desktop replaying the public Mooncake FAST'25 production trace (16,384 mock GPU blocks, 24 concurrent event-processing threads), the Flash Indexer sustains 170M ops/s -- 42x faster than the radix tree shipped in Dynamo v0.1.0 (4M ops/s) and 440x faster than the naive nested-dict implementation (385K ops/s). `evergreen`
