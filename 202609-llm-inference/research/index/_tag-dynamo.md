- [[router-design-nvidia-dynamo-documentation]] — Router Design | NVIDIA Dynamo Documentation — NVIDIA Dynamo's KV Router design doc — the closest direct architectural comparator to llm-d's inference-scheduler/EPP. The router tracks three per-worker metrics: potential decode blocks, potential new prefill blocks (computed as (total input tokens - overlap_blocks*block_size)/block_size), and active requests. Block tracking splits into locally-tracked 'active decoding blocks' and globally-tracked 'cached blocks' maintained by a KvIndexer that builds a prefix tree from worker-reported KV events (published by a KVPublisher on block-store and block-evict). Routing cost formula: cost = prefill_load_scale * adjusted_prefill_blocks + potential_decode_blocks + active_request_blocks, where adjusted_prefill_blocks subtracts a decaying overlap_score_credit (weighted separately for device/host/disk cache tiers) from raw prefill blocks, clamped at zero; the worker with lowest cost is selected (or softmax-sampled if router_temperature > 0). Gives a concrete worked example: Worker 2 with 10 raw prefill blocks, 5 device-overlap blocks, 5 decode blocks scores cost=10 (5+5), beating Worker 1 (cost 18) and Worker 3 (cost 11). KV block management flow: tokenize -> partition into fixed-size blocks (16 or 64 tokens) -> hash each block (LoRA-adapter-aware) -> lookup -> allocate or evict (LRU/LFU) -> compute. Event transport uses fire-and-forget pub/sub (NATS Core or ZMQ) with per-worker monotonic event IDs and gap detection triggering full-state resync; multi-router deployments optionally exchange AddRequest/MarkPrefillCompleted/Free lifecycle events for cross-replica active-load estimates without synchronizing prefix-cache state itself. Explicitly credits vLLM's PagedAttention and SGLang's RadixAttention as the two techniques underlying its KV cache optimization. `evergreen`
