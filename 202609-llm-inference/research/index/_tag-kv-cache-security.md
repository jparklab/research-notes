- [[governing-the-kv-cache]] — Governing the KV Cache: — Presents KVGov, a governance layer defending multi-tenant vLLM/SGLang/LMCache deployments against KV-cache timing side-channel attacks (PROMPTPEEK, EarlyBird, InputSnatch) that reach up to 100% attack success rate (ASR) by probing time-to-first-token (TTFT) to infer cache hit/miss and reconstruct victim prompts. Core mechanism is HMAC-keyed namespace isolation: a per-principal salt seeds the block-hash chain (sigma_p = HMAC_K(secret, principal_id)), making cache keys cryptographically disjoint across tenants; an ablation (N=1000 trials) shows HMAC-salt alone is necessary and sufficient to drive all three attacks to 0% ASR, with per-request HMAC overhead of only 1.3us. A 'boundary salting' variant seeds the chain only at the point where a shared preamble diverges into private content, retaining an estimated 93% of prefix-cache benefit (92.8% at a 2000-token shared preamble with 119-token private tail) instead of destroying all cross-tenant reuse. The paper also proposes ORIGAMI, a Stackelberg water-filling audit scheduler (12.6% reduction in adversary expected utility at Gini=0.63 enterprise heterogeneity) and an evolutionary-stability analysis identifying a 31.6% adversary-prevalence tipping point below which global (shared) caching remains stable versus per-session ephemeral caching. Real hardware measurements on Qwen2.5-7B-Instruct/vLLM 0.26.0/A100 show a gate-verified cold/cached TTFT ratio of 0.22 (149.6ms cold vs 32.8ms cached at a 2119-token shared prefix; 0.37 ratio at 1447 tokens), replicated on llama.cpp/Apple Metal (ratio 0.093), confirming the channel is a property of prefix caching generally, not one engine's allocator. Critically, the paper shows vLLM 0.26.0's removal of block-size=1 (raising EarlyBird's search cost to infeasibility for free-text) provides NO protection against template-structured enterprise prompts, where membership/confirmation queries against a known field remain O(1) regardless of block size — a ~75-order-of-magnitude gap between reconstruction and confirmation cost on the identical cache. `evergreen`
- [[i-know-what-you-asked-prompt-leakage-via]] — I Know What You Asked: Prompt Leakage via — Primary source (NDSS 2025) for PROMPTPEEK, the third timing side-channel attack cited by KVGov. First security investigation of multi-tenant LLM serving's KV-cache sharing (vLLM, SGLang), showing that sharing KV cache across users for identical token prefixes creates a side channel: an attacker can monitor changes in serving order/latency to detect KV cache hits and extract another user's prompt one token at a time, iteratively reconstructing the full prompt (rather than only approximating content, as prior work did). Evaluated on Llama2-13B on an A100 80GB GPU across three adversary-knowledge scenarios and four datasets: with knowledge of the prompt template, average success rate of 99% fully/partially reversing the prompt input; with knowledge of the prompt input, 98% reversing the prompt template; and with no background knowledge at all, 95% success. Identifies three factors governing attack feasibility: GPU memory capacity (sets whether the attack is feasible at all), concurrent user request volume, and attacker request volume (both accelerate memory-driven cache eviction/exposure), plus attacker background knowledge (reduces the number of requests needed). Demonstrates low attack cost in a concrete case: with knowledge of the prompt template, an adversary can uncover a victim's gender, age, weight, and height fields using just 60 total requests. The authors responsibly disclosed findings to SGLang (primary target), OpenAI, ByteDance, and Anthropic, and report ByteDance acknowledged the new side-channel vector. `evergreen`

Proposes a timing-based side-channel attack against two cache mechanisms (prefix/KV caching and semantic caching) using two components: an input constructor (ML models + LLM-based vocabulary-correlation learning with optimized search) that generates candidate inputs likely to hit the victim's cached state, and a time analyzer that applies statistical time fitting with outlier elimination to distinguish cache hits from misses and feeds results back to refine the constructor's search. Against prefix/KV caching, the timing analyzer achieves 87.13% accuracy in determining cache-hit prefix length. Against static-template medical question-answering systems, the attack achieves a 62% success rate extracting exact disease-name inputs and 13.5% for exact symptom descriptions; against legal-consultation RAG services using semantic caching, semantic-level extraction success rates range from 43% to 100% across thirteen legal domains. Distinguishes itself from prior prompt-theft work (adversarial prompting, embedding inversion, next-token-probability exploitation) by requiring neither white-box model access nor unlimited querying across the full vocabulary, and by targeting structured/templated enterprise prompts where the unknown content is a bounded field rather than open vocabulary. `evergreen`
- [[prefixwall-mitigating-prefix-caching-side-channels-in-shared-llm-systems]] — PrefixWall: Mitigating Prefix Caching Side Channels in Shared LLM Systems — Presents PrefixWall (IMDEA Software Institute / UPM), a vLLM-based system defending multi-tenant Automatic Prefix Caching (APC) against timing side-channel prompt-stealing attacks without the throughput loss of prior full user-level isolation defenses. Rather than isolating entire users, PrefixWall tags each KV cache entry with two metadata fields (immutable OwnerID set at allocation, and a mutable AttackFlag) and runs a Detector that flags a prefix as isolated the first time it is hit by a non-owning user; subsequent non-owner requests are blocked from reusing anything beyond the flagged boundary and are recomputed, while the original owner can continue extending their own path unrestricted even through flagged nodes. A second component, the Activator, continuously computes the Kernel Density Estimation (KDE) overlap between the hit-latency and miss-latency TTFT distributions over a sliding window; when overlap exceeds an admin-set threshold theta (meaning hits/misses are statistically indistinguishable, e.g. under high load/batching), isolation is deactivated entirely to preserve cache reuse, since the side channel is not exploitable in that regime. The paper gives a formal security guarantee: for any probing sequence targeting a secret entry with a non-empty known prefix, if the prefix's final entry is already flagged OR the attacker's first guess is wrong, all subsequent probes from a different principal return misses — with two explicit gaps: (1) no protection for attacks on the very first prompt entry (no parent node to flag; mitigated in practice because OpenAI-style deployments only cache prefixes above ~1024 tokens and hit/miss distributions overlap heavily for single-entry prefixes even at large model sizes), and (2) no protection if an attacker guesses the secret correctly on the very first probe. Evaluated on an A100 (40GB) running vLLM 0.8.5 (block size 16) across nine models (0.5B-13B, Gemma3/Llava/Llama2/Qwen2/Qwen2.5 families), PrefixWall achieves up to 70% higher cache reuse and 30% lower inference latency than full user-level-isolation baselines, with negligible runtime/memory overhead, while empirically closing the measured timing leak across cross-user requests. `evergreen`
- [[the-early-bird-catches-the-leak-unveiling-timing]] — The Early Bird Catches the Leak: Unveiling Timing — Primary source for the EarlyBird attack cited by KVGov. First security analysis of LLM serving performance optimizations across multiple users, identifying two exploitable timing side channels: (1) KV-cache sharing across requests with common prefixes, and (2) semantic caching that serves cached responses for similar queries (with cache hits producing a sharp TTFT drop from ~5s to under 1s that far exceeds network jitter). Introduces a token-by-token search algorithm (Predict-and-Sample-Attack, PSA) that uses a next-token predictor plus a TTFT classifier to iteratively recover shared system/victim prompts one token at a time, and a Prompt Nearest-neighbor Attack (PNA) targeting semantic caches by testing privacy-related prompt templates and monitoring TTFT for semantic-match hits. Black-box evaluation against popular online LLM services (via SGLang backend) reports a token-recovery success rate of 89.0% with a false positive rate of 0.04, averaging 5.64 guesses and 112.72 attack queries per recovered token (n=10 trials per position), at an attack cost of approximately /bin/bash.16/token with OpenAI o1, /bin/bash.012 with OpenAI o3-mini, and /bin/bash.001 with DeepSeek-Chat (pricing as of March 5, 2025). Across 200 victim prompts, the attack recovered an average of 11.32 tokens for the top 100 prompts and 17.84 tokens for the top 50, with a maximum of 81 tokens recovered for a single prompt using 519 total guesses. Using an untuned generic predictor (Llama-3.1-8B-Instruct) instead of a fine-tuned one drops recovery rate to 69% and raises average guesses per token from 5.64 to 163.48 (5,231.30 attack queries), demonstrating the attack degrades but remains viable without a specialized predictor. Also demonstrates cache eviction can be forced without privileged APIs: sending 15 irrelevant ~200-token requests reliably (100% of 10,000 tests) triggers SGLang's default eviction policy within about 5 seconds, letting an attacker reset cache state as part of the attack loop. `evergreen`
