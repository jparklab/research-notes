- [[kv-cache-events-synchronization-aibrix]] — KV Cache Events Synchronization — AIBrix — AIBrix (ByteDance's Kubernetes-native vLLM control plane) documentation for KV Cache Events Synchronization, an alternative to llm-d's KV-event design: vLLM instances publish BlockStoredEvent (BlockHashes, TokenIDs, ModelName, LoraID, SourcePod, ParentBlockHash) and BlockRemovedEvent messages over a ZMQ pub/sub pattern (ports 5557 for events, 5558 for replay) to an in-gateway KV Event Manager, which feeds a Sync Prefix Cache Indexer maintaining global prefix cache state for the Gateway Router. The feature has a strict hard dependency on a remote tokenizer being enabled (AIBRIX_PREFIX_CACHE_USE_REMOTE_TOKENIZER=true) to guarantee identical tokenization between gateway and vLLM workers — the system refuses to initialize KV sync without it — and requires vLLM >=0.7.0 with KV cache events support plus gateway-plugins built with libzmq3-dev (-tags="zmq"). Routing selects pods by prefix-match percentage (descending) then running-request count (ascending), picking the first pod satisfying running_requests <= mean + STANDARD_DEVIATION_FACTOR * sigma, falling back to the globally least-loaded ready pod if no matched pod clears that bar; a separate, centrally-applied load-imbalance gate runs ahead of whichever routing strategy is active. Documented resource costs: ~1MB/s ZMQ traffic per vLLM pod at high load, ~64 bytes per prefix entry in the sync indexer, and <1% CPU overhead per pod. `evergreen`
