- [[tokenlake-a-unified-segment-level-prefix-cache-pool]] — TokenLake: A Unified Segment-level Prefix Cache Pool — TokenLake (Peking University + StepFun) diagnoses three structural failure modes of instance-local cache-aware routing (the prefix-tree-per-instance model used by systems like llm-d's KV-cache-aware router, SGLang, Mooncake): (1) load imbalance -- instances with high prefix hit rates become memory-bandwidth over-utilized while cold instances sit idle, because the router can only route whole requests to whichever instance already holds the matching prefix tree; (2) redundancy -- to rebalance computation, hot shared prefixes (system prompts, shared documents) get replicated across multiple instances, wasting memory; (3) fragmentation -- because a full prefix must reside on one instance to form a contiguous prefix tree, memory slots scattered across instances cannot be pooled together. These problems compound under PD (prefill/decode) disaggregation, since prefill and decode instances have different memory-bandwidth profiles and must each separately hold the same prefix cache to avoid recomputation. TokenLake's fix decouples cache management from scheduling via a declarative interface (exposing query tensors, prefix caches, and cache-aware ops) and manages cache at sub-request segment granularity with a heavy-hitter-aware load-balancing algorithm, letting the scheduler dispatch elastically without needing to track prefix locality. On real-world workloads (CharacterAI/Kimi report 75-95% production hit rates as baseline context), TokenLake improves throughput up to 2.6x and 2.0x and cache hit rate up to 2.0x and 2.1x versus state-of-the-art cache-aware routing and cache-centric PD-disaggregation baselines respectively. `evergreen`
