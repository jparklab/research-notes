- [[kv-cache-management-llm-d]] — KV Cache Management | llm-d — llm-d dev-version overview page defining KV cache management as three composable architectural pillars: (1) Prefix-Cache Aware Routing — the EPP-managed intelligence layer that routes requests to replicas already holding the relevant KV cache, offered in Approximate (heuristic) and Precise (event-driven) variants; (2) KV-Cache Indexing — the observability layer consuming high-frequency KVEvents from engines like vLLM to track block movement/eviction across offloaded tiers; (3) KV Offloading — the capacity layer that spills cache to CPU memory or SSD beyond GPU HBM limits. Also introduces a fourth layer, P2P Sharing, which composes the other three into a fleet-wide cache: the index identifies which peer holds a prefix, the router stamps the request, and the model server pulls blocks directly from the peer's CPU offload tier over NIXL without touching the source pod's GPU; a promised-but-undelivered block degrades to normal recompute rather than failing the request. `evergreen`
