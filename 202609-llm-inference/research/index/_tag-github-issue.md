- [[kvblock-inmemoryindexlookup-tests-emptiness-and-reads-entries-without-the-pod-ca]] — kvblock: InMemoryIndex.Lookup tests emptiness and reads entries without the pod-cache lock · Issue #2698 · llm-d/llm-d-router — GitHub issue #2698 (opened Sep 4, 2026, llm-d/llm-d-router, by collaborator nilig) is a precise concurrency-bug writeup in kvblock.InMemoryIndex.Lookup: the method checks whether a key's pod-cache is empty and then reads its holder keys as two SEPARATELY locked calls (not atomic), even though PodCache.mu exists for exactly this purpose and writers (Add, Evict) correctly hold it across their check-then-act sequences. If a concurrent Evict or Clear removes the last entry for a key between Lookup's two calls, Keys() returns empty, causing (1) the unfiltered branch to assign an empty slice into the result map -- producing a key that is 'present but held by nobody,' contradicting the early-stop guard meant to prevent exactly this -- and (2) the prefix-chain-break check being skipped in both branches, letting the returned map carry keys from beyond where the chain should have stopped. States the bug does NOT corrupt routing today because the downstream matcher walks keys in order and stops at the first empty-entries key regardless, so the cost is only wasted lookups/materialization, not wrong routing decisions. The visible symptom was in telemetry: keysFound counted map entries rather than entries-with-holders, so an empty key was published as a false block-hit; PR #2669 already fixed the metric by counting only keys with >=1 entry. The full fix, PR #2680, rewrites Lookup to read entries and count in a single critical section under PodCache.mu via a new PodCache.filteredEntries method, storing a result only when the filtered slice is non-empty. Notes this is not a Go data race (go -race will never catch it) since each locked call is individually safe -- only the sequence across calls is wrong -- and the race window is only a few instructions wide, though evictions run continuously from BlockRemoved events, pod clears, and LRU capacity pressure. `evergreen`
