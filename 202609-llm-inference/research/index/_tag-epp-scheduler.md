Features: KV cache usage %, input length, queue depth, running requests, prefix cache match %, and input tokens in-flight. The model retrains continuously on a bucketed sliding window (stratified by KV-cache % and prefix hit-rate bands) to avoid forgetting rarer traffic regimes. Deployed as a training/prediction sidecar pair to the Gateway API Inference Extension's Endpoint Picker (EPP); a predicted-latency scorer computes 'headroom' (predicted latency minus SLO target, weighted 80% TTFT/20% TPOT by default) and does best-fit packing when SLOs exist, else routes to lowest predicted latency. A cache-aware affinity gate (epsilon-greedy, default affinityGateTau=0.80, epsilonExploreSticky=0.01, affinityMaxTTFTPenaltyMs=5000ms) prevents pure-greedy routing from fragmenting the cache: it exploits cache-warm pods 99% of the time and explores non-sticky pods 1% of the time, with a load override if the warm pod's predicted TTFT exceeds the best pod's by more than the penalty threshold. Achieves ~5% MAPE on TTFT/TPOT prediction. Across 5 synthetic benchmark scenarios (10x H100 pods, Qwen3-class models) spanning cache-friendly to cache-intensive regimes, predicted-latency scheduling beats or matches load+prefix-aware routing in 4/5 cases; only under extreme system-cache churn (Workload C) does it merely tie. On a production-derived Qwen3-480B workload (13 servers x 8 H200, ~94% peak cache hit rate with frequent collapses), predicted-latency routing cut E2E p50 latency 43% (9.06s vs 13.42s for hand-tuned weights) and TTFT p50 70% (0.97s vs 3.38s) versus the best heuristic scorer, without workload-specific tuning. Prediction serving scales to 10,000 QPS across 100 candidate pods using request coalescing (1ms batching window) and horizontally-scaled prediction servers (28 uvicorn workers each). `evergreen`
