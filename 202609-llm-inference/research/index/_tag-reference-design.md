- [[blocking-queries-consul-hashicorp-developer]] — Blocking Queries | Consul | HashiCorp Developer — Official Consul blocking-queries semantics. Mechanism: endpoints that support blocking return header X-Consul-Index (a raft-index snapshot marker); client resends the same request with query param index=<last X-Consul-Index> plus wait=<duration> (max 10m, default 5m, plus up to wait/16 jitter) and the server holds the HTTP request open until a change occurs past that index or the timeout elapses -- long polling, not a persistent stream. Quote: 'the return of a blocking request is no guarantee of a change' (timeout or an idempotent write can return with no actual change). Implementation-detail requirements a client MUST follow: (1) reset index to 0 if a returned index is LOWER than the previous value (raft snapshot restore, KV list edge cases, Consul upgrades changing watch granularity) -- failing this can miss updates indefinitely or busy-loop; (2) sanity-check index > 0 after each response, since index=1 is always safe to request for not-yet-existent data; (3) rate-limit the blocking loop client-side (token-bucket, burst ~2) to avoid degrading into a busy loop when data churns fast, rather than sleeping (which delays delivery). Streaming backend (Consul 1.10+) is a materialized-view alternative to long polling, engaged automatically when index or cached params are set if the endpoint supports it; it omits X-Consul-LastContact/X-Consul-KnownLeader and marks responses with X-Consul-Query-Backend: streaming. A minority of agent-local endpoints (state not raft-indexed) instead use hash-based blocking: header X-Consul-ContentHash + query param hash=<value>, opaque (not orderable), otherwise same wait/timeout contract. RELEVANCE TO LOCUS: this is the direct analog to a poll-vs-watch decision for a Consul-backed EndpointDiscovery plugin -- a plugin would issue a blocking GET against /v1/health/service/:service with index tracking (see companion note health-http-api-consul-hashicorp-developer for the passing=true health-filter parameter), not a bare interval poll, to get near-real-time updates without tight polling. `evergreen`
