summary: 'One-line Helm-chart diff for GIE PR #2061 (''fix prometheus auth'', sallyom,
  merged Jan 5 2026, fixes issue #2060) in config/charts/inferencepool/templates/epp-deployment.yaml:
  changes the guard controlling the EPP container''s --metrics-endpoint-auth=false
  flag from ''{{- if not .Values.inferenceExtension.monitoring.prometheus.enabled
  }}'' to ''{{- if not .Values.inferenceExtension.monitoring.prometheus.auth.enabled
  }}''. Before the fix, simply enabling Prometheus scraping (monitoring.prometheus.enabled=true)
  was sufficient to leave --metrics-endpoint-auth at its (implied) default of true/on
  regardless of whether the separate auth.enabled sub-value was actually set, i.e.
  auth state was wrongly tied to whether Prometheus monitoring was enabled at all
  rather than to a dedicated auth toggle. After the fix, metrics auth is disabled
  only when the chart''s new nested monitoring.prometheus.auth.enabled value is explicitly
  false, decoupling ''is Prometheus scraping configured'' from ''is bearer-token/mTLS
  auth on the metrics endpoint required'' at the Helm-values level.'
